# 2026-10-07 既存テーマの採用確認通知を修正

## 原因

候補選択で採用記録の取得を先に行っていた。そのため、既存記事と同じテーマでも採用記録がないと `topic_adoption_missing` となり、採用状態の保存を先生へ求めていた。これでは既存記事との一致を確認する処理に到達しない。

また、既存の通知は `precheck_related`（内容が関連している可能性）を完全一致と同じ「重複を避けて見送り」にまとめていた。

## 修正

- 予定日前の候補を除外した後、採用記録取得の前に既存の比較メタデータで照合する。
- 既存の `localComparisons` を一度の選択中に遅延取得し、候補間で同じスナップショットを利用。取得・検証失敗は `comparison_metadata_unavailable` として運用側の確認対象にする。例外本文は通知に渡さない。
- 正規化後のタイトル完全一致、または既存メタデータの元テーマID一致は `duplicate_metadata`。
- 語句から関連が疑われる場合は別の `metadata_related`。内容の重複が確定したとは扱わない。
- 関連の判定は限定的な補助規則で、①両方が「定期検診」と頻度・受診間隔に関する語を含む、または②正規化後の先頭10文字以上が一致し、2文字単位の共通度（Dice係数）が0.5以上、の場合。カテゴリ一致や「受診の目安」だけでは判定しない。
- `metadata_related` と既存の `precheck_related` は通知上も完全一致と別の件数・説明に分ける。採用し直す操作を求めない。自動の追加調査を開始したという表現は使わない。
- 既存記事と異なる候補は従来どおり採用記録を確認する。既存枠の記事の再試行、サーバーの prepare、比較hashの再確認、採用証跡・公開条件、通知重複防止は変更しない。

## 限界

この語句比較は意味の同一性を証明しない。異なる切り口を保留する可能性も、言い換えを見逃す可能性もある。保留によって生成を許可することはなく、採用済みの別候補は従来の審査を通る。既存CSV・候補・記事・採用記録は変更しない。
