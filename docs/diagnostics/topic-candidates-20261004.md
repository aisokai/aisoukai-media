# 2026-10-04 月次候補の操作と再提案の修正

## 確認した原因

- 状態フィルターの初期値が「すべて」で、保存後も同じ候補が条件に一致するため、`router.refresh()` だけではカードが残った。
- 生成器は固定24テーマを毎月そのまま選び、記事タイトルとの重複は注意度を付けるだけだった。過去の月次候補は比較していなかった。
- Managerのメタデータ照合では10月・11月の24タイトルがすべて同一。11月の既存判断（採用3件、却下4件）は修正対象外。

## 修正

- 初期表示を未判断にし、対象月・未判断残数・判断済み候補を再確認する方法を表示。
- サーバー保存成功後だけカードを保存完了表示へ置換。失敗・結果不明はカードを残してアクセス可能なエラーを表示。結果不明時は「変更していない」と断定しない。
- 各状態フィルターや「すべて」から保存済み候補を再確認可能。「未判断に戻す」も追加。フィルターごとにカードを再生成し、閉じた状態が別フィルターへ残らない。
- 現在と前月の2つのスナップショットだけで、前月にもある同一テーマを表示上で注意喚起。タイトル・判断は保存変更しない。照合不能を新規扱いしない。
- 今後の生成では、過去月の候補（却下・保留を含む）と記事の公開編集メタデータに一致するタイトルを除外。NFKC、大小文字、空白・句読点の差を正規化。同義の別表現まで完全判定する機能ではない。
- 固定在庫が24件に満たなければ不足数を報告して保存しない。既存validatorの24件条件を維持し、無理な穴埋めをしない。
- 既存出力があれば拒否し、作成時も `wx` で排他的に保存。既存判断を上書きしない。有効な月の形式を検証。
- 記事本文は読取対象にせず、frontmatterの境界までバイトとして取得して既存のメタデータ抽出器を使用。比較に不要な値を出力しない。
