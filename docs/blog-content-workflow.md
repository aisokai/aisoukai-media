## 記事追加フロー（Phase 1 詳細）

```
┌─────────────────────────────────────────┐
│  コンテンツ企画                          │
│  - テーマ決定（患者の疑問・症状起点）    │
│  - カテゴリ・キーワード選定              │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  重複チェック                            │
│  ls content/posts/ | grep {keyword}     │
│  既存記事と被っていないか確認            │
└────────────────┬────────────────────────┘
                 │ 重複なし
                 ▼
┌─────────────────────────────────────────┐
│  slug 決定                              │
│  形式: YYYY-MM-DD-{topic-en}.md         │
│  例: 2026-06-01-fluoride-for-kids.md    │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  Markdown 作成                          │
│  - frontmatter（スキーマ準拠）          │
│  - 本文（見出し2〜4個、800〜1200文字）  │
│  - 断定表現・医療効果表現がないか確認   │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  ローカル確認                            │
│  npm run dev                            │
│  → /blog/{slug} が 200 で表示           │
│  → カード・サイドバーに記事が出ている   │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  ビルド確認                              │
│  npm run build                          │
│  → エラーなし                           │
│  → /blog/{slug} が SSG リストに出る     │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│  デプロイ（Phase 1: 手動）              │
│  git add content/posts/{slug}.md        │
│  git commit -m "content: add {theme}"  │
│  git push（将来: CI/CD が自動 deploy）  │
└─────────────────────────────────────────┘
```

## 記事テンプレート（コピー用）

```markdown
---
title: ""
date: "YYYY-MM-DD"
excerpt: ""
category: ""
tags:
  - 
  - 
---

## はじめに

（導入文：患者が抱える疑問・背景を共感的に述べる。2〜3文）

## {メインテーマ1}

（本論1：原因・仕組み・特徴などを解説。断定表現を避ける）

## {メインテーマ2}

（本論2：治療・対処・予防など）

## {メインテーマ3}（任意）

（本論3：注意点・よくある誤解など）

## まとめ

（要点を2〜3文でまとめる。受診を促す場合も断定しない）
```

## AI 記事生成プロンプト（Phase 2 用）

```
# 歯科メディア記事 ドラフト生成依頼

## 仕様ファイル
docs/blog-article-schema.md を参照

## 記事条件
- category: {カテゴリ名}
- テーマ: {テーマ}
- 想定キーワード: {SEO キーワード}
- 想定読者: {ペルソナ}
- 文字数: 800〜1200文字（本文のみ。frontmatterは含まない）

## 制約
- 医療効果の断定禁止（「必ず治る」「完全予防できる」等）
- 「有効とされています」「可能性があります」「といわれています」など慎重な表現を使う
- クリニック名は「三谷ファミリー歯科クリニック（医療法人藍想会）」
- 架空の統計・研究を捏造しない

## 出力形式
frontmatter + 本文 を Markdown でそのまま出力。説明・補足は不要。
slugは YYYY-MM-DD-{topic-en}.md 形式で date に合わせる。
```

## Human レビュー境界（詳細）

### AI に任せてよい作業

- 記事の構成案（見出し一覧）
- 各段落のドラフト文章
- tags・excerpt の候補生成
- slug のトピック部分の英訳候補

### Human が必ず確認する項目

| チェック項目 | 確認方法 |
|------------|---------|
| ① 医療断定表現がない | 全文を読んで「必ず」「確実に」「治ります」がないか |
| ② 事実関係の正確さ | 治療名・薬品名・統計数値が正確か |
| ③ クリニック情報の整合性 | 院名・診療科目・所在地（徳島県）が正しいか |
| ④ frontmatter 完全性 | 必須フィールドが揃っているか |
| ⑤ slug の重複なし | `ls content/posts/ | grep {keyword}` で確認 |
| ⑥ ビルド通過 | `npm run build` がエラーなく完了するか |

### レビュー後の修正

- 軽微な表現修正: そのまま編集 → 追記なし
- 事実関係の誤り: 該当箇所を削除または修正 → 医師・専門スタッフへ確認を推奨
- 構造的な問題（テーマ重複・カテゴリ誤りなど）: ドラフトを破棄して再生成
